## Problem Statement

When an engineer leaves an organization, institutional knowledge is lost. Successor engineers often spend weeks manually sifting through Git commit messages, merged pull requests, and abandoned issue threads to answer essential operational questions:

- Who actually built and maintains each module?
- What features or refactors are half-finished, blocked, or in review?
- Why were key architectural decisions and tradeoffs chosen?
- What are the undocumented dependencies, deployment pitfalls, and single points of failure?

HandoverIQ eliminates this ramp-up bottleneck by synthesizing an authoritative, evidence-backed handover dossier directly from repository history.

---

## Core Capabilities

### 1. The 5-Pillar Handover Schema
HandoverIQ organizes all repository intelligence into five structured categories:

1. **Ownership and Core Modules**: Maintainer contribution share, primary code authors, and domain expertise mapping.
2. **Unfinished Work and In-Flight Tasks**: Active pull requests, pending code reviews, and blocked issues.
3. **Architectural Decisions and Context**: The rationale behind system changes as documented in commit messages and pull request discussions.
4. **Dependencies and Setup Context**: Runtime stacks, build configurations, and dependency modifications.
5. **Risks, Technical Debt and Blockers**: Defect clusters, single points of failure, bus-factor vulnerabilities, and stale tasks.

### 2. Strict Evidence Linking
Every claim and insight generated by HandoverIQ links directly to verified GitHub artifacts (exact commit SHAs, pull request numbers, or issue URLs). There are no unattributed summaries or ungrounded assertions.

### 3. Knowledge Gap Detection and Reviewer Checklist
Identifies operational blind spots (such as missing deployment documentation, unconfigured secrets, or undocumented rollback steps) with an interactive checklist allowing engineers to mark items as resolved or append custom handover queries.

### 4. Repository Readiness Benchmark Matrix
Enables side-by-side transition readiness comparisons across repositories. Evaluates bus-factor resilience, open gap counts, and overall maintainability scores to highlight offboarding risks prior to engineer departure.

### 5. Offline Standby and Rate-Limit Resilient Recovery
Includes automated fallback indexing for standard benchmark repositories, ensuring that evaluations and presentations continue seamlessly even if public GitHub API rate limits are reached.

### 6. Executive PDF and Print Export
Formats dossiers for executive reporting, compliance archiving, and offboarding sign-offs with clean print and PDF export styling.

### 7. Engineering Transition Badges and Ranks
Provides milestone-based progression (Cadet Explorer to Staff Handover Architect) that tracks and rewards team members as they resolve handover gaps, audit repositories, and export dossiers.

## Getting Started Locally

### Prerequisites
- Node.js 18+ and npm
- Python 3.10+
- Git

### 1-Click Launch (Windows)
```cmd
start-all.bat
```
- Frontend: http://localhost:3000
- Backend: http://localhost:8000
- Interactive API Docs: http://localhost:8000/docs

### Manual Launch

**Backend:**
```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Frontend:**
```bash
cd frontend
npm install
npm run dev
```
